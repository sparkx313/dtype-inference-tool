  reservoir         20000        1000     0.6500        140        email

  same types either way. Full scan peak goes from 351 KB at 2000 values to
  2089 KB at 20000 values - it grows with the column. The reservoir holds 140 KB
  at both sizes, and is the only option when the column will not fit in
  memory. Sampling is why the 1000-value default costs the same for a
  10k-row and a 10M-row table.

  times are for 2000 values of that column; every column is scored against
  all 13 candidates, so the scoring pass costs the sum of a row above.
  The two cells that stand out are the date parser run over email/url/
  text and the datetime parser run over url: those values are long, so
  each separator split produces a substring long enough to try, and
  nothing matches until the whole value has been worked through. The
  cheap guards - a colon test before the datetime scan, a letter test
  before `strptime` - are what keep the other cells near zero.
